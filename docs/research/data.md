# Free NFL stats, usage & matchup/scheme data

## SUMMARY
## Free NFL data, usage and matchup/scheme data: what's usable in October 2026

**The nflverse pipeline is working for the 2026 season. The release `timestamp.json` files I fetched on 2026-10-15 show that every main dataset updated within the last 1–3 days.** That covers pbp, player and team stats, rosters, depth charts, injuries, NGS, PFR advanced stats, snap counts, FTN charting, schedules and ESPN QBR. I checked this by cloning the nflverse repos and fetching release assets directly, not from memory. Data for weeks 1–5 is present, and the week 6 injury and practice report is already in.

**What changed or broke since 2024:**
- **Injuries:** the old source stopped after the 2024 season. A new NFL-API source (`nflapi`) started in August/September 2026, and 2025 was backfilled. The 2026 file has **one row per player per week** with the latest status only. It has no Wednesday/Thursday/Friday practice progression and no `date_modified`. To get the practice trend, snapshot it daily yourself.
- **Depth charts:** the source changed to ESPN in 2025. Each update is a timestamped snapshot (`dt`); there is no week field. The 2026 CSV is 62 MB, against 2.9 MB for the parquet. The data includes **LCB/RCB/NB (nickel)** labels, which is a useful free signal for slot-corner matchups.
- **Participation (personnel, formation, man/zone, coverage shell, pressure, time to throw):** FTN supplies this **only after the season ends**. 2025 was published on 2026-02-10. **There is no free in-season 2026 man/zone data in nflverse.**
- **PFR (snap counts, advanced stats):** Pro-Football-Reference now blocks bots. Since September 2026 nflverse scrapes it through a paid proxy service (ScrapeOps), and there were repeated workflow failures that month. It is fragile but current: snap counts updated 10-13 and advanced stats 10-15.
- **Smaller changes:** the `qs` format was dropped (January 2026), and the officials workflow is disabled.

**Browser access: an ETL step is required.** Release asset URLs return a 302 redirect to `release-assets.githubusercontent.com` with **no `Access-Control-Allow-Origin` header**, which I confirmed with curl. Files in git repos on `raw.githubusercontent.com` do send `access-control-allow-origin: *`. That covers nfldata `games.csv` and DynastyProcess `db_playerids.csv` / `fp_latest_weekly.csv`. However, GitHub tightened limits on unauthenticated raw downloads in May 2025.

Recommended setup:
- A scheduled GitHub Actions job using nflreadpy 0.1.7 (Polars) or DuckDB.
- It downloads the parquet files, computes compact JSON aggregates and publishes them to the app's own GitHub Pages site, so the app reads from its own domain.
- Schedule it at odd minutes. nflverse itself moved off on-the-hour cron times to avoid GitHub delays, and uses monthly keep-alive commits.
- Re-pull on Thursday, because NFL stat corrections land Monday–Wednesday.

**Usage metrics you can compute for free:**
- Directly in `stats_player`: target share, air-yards share, WOPR, RACR, EPA, PPR points.
- From pbp (372 columns): red-zone and inside-10/5 rush share, end-zone targets, and RB opportunity share.
- From ffopportunity: expected fantasy points (xFP). It is an xgboost model trained on 2006–2020 pbp. Its scoring is hard-coded PPR, but it outputs each component separately, so you can rescore it to any league's settings.
- **Routes run are not in any free in-season dataset.** I checked the proxy "dropbacks while on the field" from 2025 participation. Ja'Marr Chase came out at 630, against 634 routes run reported by SumerSports, so it is very accurate for WRs. It overstates routes for TEs and RBs, who sometimes stay in to block. In-season, estimate routes as snap% × team dropbacks and label it as an estimate. TPRR and YPRR are therefore proxies too.

**Matchup and scheme data:**

| Data | Free? | Where / what to do |
|---|---|---|
| WR vs CB, shadow coverage, CB/WR alignment, slot rate, receiver man/zone splits per route | Paid only | PFF+ costs $9.99/month or $99.99/year per PFF's 2026-09-01 pricing post; PFF Pro is listed at $199.99/year, "coming soon". FantasyPoints Data price not verified. SIS and TruMedia sell to businesses only. |
| CB quality and coverage | Free proxy | PFR defensive advanced stats give **per-defender targets, completions, yards, TDs, passer rating and aDOT allowed, per game, in-season**. Combine with ESPN depth-chart LCB/RCB/NB roles, CB injury reports, and NGS receiver cushion/separation (only players with 5+ targets that week). |
| Man/zone and coverage shells, 2026 in-season | Not in free structured data | Shown on free web pages (StatRankings, Sharp Football, SumerSports) but none has an API, and scraping risks their terms of service. 2023–2025 play-level shells (Cover 0/1/2/3/4/6/9, 2-Man) are free in participation data. Use them as priors and shrink them hard when a team has a new defensive coordinator. |
| Blitz and pressure | Free | FTN charting has `n_blitzers` and `n_pass_rushers` in-season. PFR has pressures, hurries and blitzes. NGS has QB time to throw. ESPN win rates are published only in articles, with no API. |
| Pace and neutral pass rate over expected (PROE) | Free | Compute from pbp using `xpass`, `pass_oe`, `wp`, `qb_dropback`. |
| Opponent-adjusted points allowed | Free | `stats_player.opponent_team` plus xFP allowed. |
| Rest, travel, roof, surface, betting lines | Free | Schedules have `away_rest`/`home_rest`, `spread_line` (positive means the home team is favored) and `total_line`. nfldata `airports.csv` gives team lat/lon and time zone. |
| Weather forecasts | Free with limits | NWS works in the browser (CORS) but covers the US only. Open-Meteo's free tier is **non-commercial only**. Game-day `temp`/`wind` in nflverse is filled in only after kickoff. |
| Play-caller | No free data | Schedules list head coaches only. Keep a hand-maintained 32-row table. |

**How to approximate CB/scheme matchups honestly:** build a matchup score from five signals:
1. Opponent's position-level xFP allowed versus expected.
2. CB room vulnerability (PFR yards per target and passer rating allowed, nickel identity, CB injuries).
3. Pass-rush and blitz profile.
4. A historical coverage-shell prior combined with the receiver's historical man/zone yards per target. The participation `route` field covers only the targeted receiver, so you have no denominator.
5. Pace, PROE and the Vegas implied team total.

Label each part "historical tendency" or "estimate", and never claim shadow coverage without paid data.

**Licensing:** nflverse data is broadly CC-BY 4.0. FTN-derived data (charting and 2023+ participation) is **CC-BY-SA 4.0** and must be credited to "FTN Data via nflverse". The underlying NFL, PFR and NGS data belongs to its owners. FantasyPros rankings come from DynastyProcess scrapes, which is a problem if you redistribute them in a commercial app.

### Net assessment
On nflverse, the report is unusually reliable. I reproduced almost every claim I could check directly from live release files and repo history on 2026-10-15: timestamps, file sizes, column lists, the injury source change and its one row per player-week, participation counts, the FTN charting layout, the PFR def advstats columns, ffopportunity scoring, games.csv fields, the CORS behaviour, the license wording, and the Chase 630/185 computation. Corrections that matter:
- nflreadpy 0.1.7 is not released (PyPI is at 0.1.5), and polars 2.0 is out, so pin both.
- Every team does list a nickel back in the ESPN depth charts.
- The cron times quoted from workflows.md are out of date (live crons use odd minutes), and real GitHub schedule delays of 4-6 hours were observed.
- The PFR/ScrapeOps story is more nuanced than reported.
- The ECR feed is PPR-only and FantasyPros-only, and the player-ID map updates weekly.

Several claims could not be checked: PFF+ pricing, SumerSports' 634 routes, StatRankings' 2026 man rates, Open-Meteo and NWS terms and CORS, and the Sports-Reference 20 req/min rule. The web search budget was used up and those hosts are blocked, so treat them as unverified. The '~1% route proxy accuracy for WRs' rests on one player.

(https://statrankings.com/nfl/advanced/teams/coverage/man-coverage-rate; https://www.sharpfootballanalysis.com/stats-nfl/nfl-coverage-schemes/; https://sumersports.com/teams/defensive/; https://pff.com/news/week-7-man-and-zone-rates-new-england-patriots-puzzling-defensive-decision)
- [medium] **Receiver man/zone splits and slot rate**: Receiver man/zone splits can be computed for free only from prior seasons and only on targeted plays (yards and EPA per target versus man or zone), not per route. Slot rate has no free source. — Participation's route and coverage fields exist only on targeted plays, so targets-vs-man share and YPT-vs-man are computable for 2023-2025, but TPRR-vs-man is not, because routes have no denominator. Slot/wide alignment: not free. Weak proxies: share of targets with pass_location == 'middle' (pbp), the ESPN WR depth slot index (unverified meaning), and NGS avg_cushion. Paid: PFF, Fantasy Points. (training knowledge + participation dictionary https://github.com/nflverse/nflreadr/blob/main/data-raw/dictionary_participation.csv)
- [medium] **Blitz, pressure and win rates**: Blitz rate and rushers are free in-season (FTN), and pressures are free per defender (PFR). ESPN's PRWR/PBWR/RSWR/RBWR are published only in articles, with no API. — FTN n_blitzers and n_pass_rushers per play give team blitz rate and average rushers. PFR def_times_blitzed, def_times_hurried, def_times_hitqb and def_pressures can be aggregated by team per week. pbp has sack and qb_hit, and NGS has QB avg_time_to_throw. was_pressure and time_to_throw per play exist only in post-season participation. ESPN win rates are built on NGS tracking: PRWR means beating a block within 2.5s. The 2025 leaderboard article was last updated through week 12, with no API or download, and scraping falls under ESPN's ToS. (https://africa.espn.com/nfl/story/_/id/46138675/2025-nfl-win-rates-top-teams-players-rankings-pass-run-block; FTN/PFR dictionaries above)
- [high LB] **Pace and neutral pass rate**: Pace, neutral-situation pass rate and PROE can be computed for free from pbp using the nflfastR xpass and pass_oe columns. — Typical neutral filter: wp between 0.20 and 0.80, downs 1-3, half_seconds_remaining > 120, excluding garbage time. Pass rate = mean(qb_dropback); PROE = mean(pass_oe). Pace = seconds per offensive play in neutral situations (from game_seconds_remaining deltas within drives) plus plays per game. No-huddle comes from pbp no_huddle or FTN is_no_huddle. Motion, play-action and screen rates by team come from FTN. (training knowledge; pbp header verified 2026-10-15)
- [high LB] **Opponent-adjusted fantasy points allowed**: Opponent-adjusted points allowed by position can be built entirely from free data: stats_player (opponent_team, position, fantasy_points_ppr) plus ffopportunity xFP allowed. — Adjust each allowed performance against the scoring player's own baseline (points over his season average, or actual minus xFP), aggregate by defense and position, and shrink with a Bayesian prior because 5-6 games is a small sample. xFP allowed separates 'they give up volume' from 'they got unlucky on TDs'. A WR1/WR2/slot split is impossible without alignment data; use depth-chart rank as a proxy. (training knowledge)
- [medium] **Weather APIs**: NWS api.weather.gov is free and works from the browser, but covers the US only and cannot receive a custom User-Agent from browsers. Open-Meteo's free tier is non-commercial only (under 10k calls/day). — NWS asks for a unique User-Agent. Browsers cannot set one, and a maintainer said the default UA is fine for client-side apps; API keys are planned with no timeline. Open-Meteo terms: free API for non-commercial use under 10,000 calls/day, 5,000/hour and 600/min. A commercial plan is needed if the app is monetized (contact Open-Meteo for pricing). International games (London, Germany, etc.) need Open-Meteo or met.no. Best design: the ETL fetches about 16 game forecasts 2-4 times per day and writes them to static JSON. Game temp/wind in nflverse schedules is filled in only after the game, so it is useless for forecasting. CORS headers on these APIs could not be tested here (sandbox blocked). (https://github.com/weather-gov/api/discussions/312; https://open-meteo.com/en/terms; https://open-meteo.com/en/pricing)
- [high] **Rest, travel and play-callers**: Rest days and neutral-site flags are in schedules, and travel can be derived from nfldata airports.csv. Play-callers (OC vs HC) are not in any free structured dataset. — away_rest/home_rest are integer days. location 'Neutral' plus stadium_id (e.g., LON00) marks international games. airports.csv gives team home-airport lat/lon and time_zone offset for distance and time-zone-shift features. Stadium coordinates need a small hand-made table. Schedules carry only head coach names, so a hand-maintained 32-row play-caller and DC table (updated on firings) is needed. With it, team-season tendencies (PROE, PA, motion, screen, shotgun, 11-personnel from historical participation) can be linked to the play-caller. (https://github.com/nflverse/nfldata/blob/master/data/airports.csv; games.csv header (cloned 2026-10-15))
- [high] **Other 2026 degradations**: Besides PFR fragility and participation being post-season only, nflverse disabled the officials workflow (the endpoint rejects requests), and GitHub Actions cron delays forced nflverse to move schedules off on-the-hour times. — nflverse-rosters commit ecc6ef1 (2026-09-15): 'Disable schedule because the workflow keeps failing... endpoint keeps rejecting the requests' (update_officials.yaml). Commit 7f6cde6 (2026-09-10): 'Use weird minutes to start workflows' to get more reliable scheduled runs. nflverse repos make monthly 'Keep GHA alive' commits. Teams release last updated 2026-03-27 (static, fine). (https://github.com/nflverse/nflverse-rosters (commit log cloned 2026-10-15); https://github.com/nflverse/nflverse-data/blob/main/workflows.md)
- [medium] **GitHub Actions/Pages operational limits**: Scheduled workflows in public repos are auto-disabled after 60 days without repo activity. GitHub Pages serves static files with permissive CORS and soft limits (~1GB site, ~100GB/month bandwidth). — Plan a keep-alive commit, as nflverse does, and use odd-minute crons (e.g., '17 */6 * * *' plus Tue/Thu re-pulls for stat corrections). Keep the published JSON small, a few MB per week of aggregates, and do not mirror raw pbp to clients. Not verifiable from this sandbox. (training knowledge)
- [low] **Sleeper stats endpoint as snap backup**: Sleeper's undocumented https://api.sleeper.app/v1/stats/nfl/regular/{season}/{week} returns per-player weekly stats, including off_snp (offensive snaps) and rec_tgt, which could back up PFR snap counts. — Field names are inferred from community wrappers, not official docs. It is keyed by sleeper_id, so map through db_playerids or weekly_rosters. Whether it includes routes or team snap totals (e.g., tm_off_snp) is unverified. (https://glama.ai/mcp/servers/justfeltlikerunning/sleeper-fantasy-mcp/tools/get_historical_scores; https://github.com/SwapnikKatkoori/sleeper-api-wrapper)

## RECOMMENDATIONS
- [MVP] Build a GitHub Actions ETL in the app repo (Python + nflreadpy/Polars or DuckDB). Cron at odd minutes: about every 6h in-season, plus after the Sunday late window, Monday night, and a Thursday stat-correction re-pull. It downloads nflverse parquet files and publishes compact per-season, per-week JSON (player usage, team tendencies, matchup tables) to the app's own GitHub Pages site. — Release assets send no CORS headers; raw.githubusercontent.com is rate-limited; pbp is about 20MB parquet per season and depth charts are 62MB as CSV. Precomputed aggregates keep the PWA fast and offline-capable, with no server.
- [MVP] MVP ingest set: schedules/games (lines, implied totals, rest, roof, surface), stats_player_week, the current-season pbp (aggregated server-side only), snap_counts, ffopportunity ep_weekly (+ ep_pbp_pass/rush for red-zone xFP), injuries (snapshot daily to rebuild the practice trend), depth_charts (latest dt only), weekly_rosters + DynastyProcess db_playerids for the sleeper_id↔gsis_id↔pfr_id joins. — These cover start/sit, waivers and trades: volume and usage, expected points, team environment and availability. All are free and updating in 2026.
- [MVP] Compute these usage metrics in the ETL: snap share; estimated routes (snap% × team dropbacks) and per-estimated-route TPRR/YPRR; target and air-yards share and WOPR from summed totals; RB opportunity share; inside-10 and inside-5 rush share; red-zone and end-zone targets; xFP and xFP share; actual minus xFP (TD luck); rolling 3- and 5-week windows with trend flags. — These are the most predictive free usage signals. Labelling route-based stats as estimates keeps the app honest.
- [MVP] Add team-environment models from pbp: neutral pass rate, PROE (pass_oe), neutral pace (seconds per play), plus Vegas implied team totals from spread_line and total_line. — Volume and scoring environment explain more fantasy variance than individual CB matchups, and all of it is free and robust.
- [MVP] Add opponent-adjusted points allowed by position: actual minus xFP allowed and points over each player's baseline, shrunk with a Bayesian prior. — This is a defensible 'matchup' number from free data and avoids the raw-points-allowed noise that most apps show.
- [MVP] Ingest FTN charting (blitz rate, average pass rushers, box count, play-action, screen, motion, RPO rates) and show 'FTN Data via nflverse' attribution in the app. — It is the only free in-season scheme data, arrives within about 48h, and is small (under 200KB parquet per season). It is CC-BY-SA, so don't republish raw derived datasets without the same license.
- [v1] Build a 'CB room vulnerability' score. Use PFR def advstats (targets, yards per target and passer rating allowed per CB, multi-week, shrunk), ESPN depth-chart LCB/RCB/NB identity and CB injury status. Combine it with NGS receiver separation and cushion where the receiver qualifies. — This is the most honest free stand-in for WR-vs-CB matchups. A CB injury (e.g., the nickel corner out) is a high-signal free input.
- [v1] Load 2023-2025 pbp_participation to build (a) coverage-shell and man/zone priors per defense, shrunk toward league average and reset heavily when the defensive coordinator changed, and (b) receiver man/zone yards and EPA per target and target share. Present both as 'historical tendency' with confidence badges. — Free play-level coverage data exists only for completed seasons. Prior-season tendencies are informative but go stale with staff and roster changes.
- [v1] Add NGS (separation, cushion, YAC over expected, rush yards over expected, time to throw) and ESPN QBR as efficiency context. Add weather forecasts fetched in the ETL (NWS for US venues; Open-Meteo or met.no for international games and as fallback) and rest/travel features from airports.csv plus a stadium coordinate table. — These add context for start/sit edge cases (wind over 15mph, short weeks, cross-country travel) at low cost.
- [v2] Keep a hand-maintained play-caller/DC table and a calibrated route-estimation model. Fit position-specific route-per-dropback factors on 2023-2025 participation (WR proxy validated at about 1% vs SumerSports for Chase), then apply them to in-season snap data. — This improves the TPRR/YPRR estimates and links scheme tendencies to coaching changes.
- [v2] Backtest the matchup layer (CB vulnerability, coverage priors, points allowed) against 2023-2025 outcomes before weighting it heavily in start/sit. Show users the incremental accuracy over projections alone. — Free matchup proxies are noisy. Backtesting prevents overconfident 'matchup' advice and supports the app's claim of calculated analysis.
- [later] If the app is monetized and users demand true WR/CB, shadow and alignment data, evaluate licensing a commercial feed (Fantasy Points Data, FTN Premium API, SIS) rather than scraping. Treat PFF+ ($99.99/yr) as a research tool for the developer, not a data source. — Consumer subscriptions do not grant redistribution rights. Commercial B2B feeds are the only clean route to per-route coverage data.
- [avoid] Do not scrape PFF, ESPN win-rate articles, SumerSports, StatRankings or Sharp Football pages. Do not fetch release assets directly from the browser or through public CORS proxies. Never present 'shadow coverage' claims without data that actually supports them. — These carry ToS and legal risk, are brittle (pages change, proxies rate-limit), and would undermine trust in the analysis.

## RISKS
- [high] PFR-sourced snap counts and advanced stats break mid-season. PFR blocks bots, and nflverse now depends on a paid scraping proxy (ScrapeOps) that failed repeatedly in Sep 2026. — mitigation: Show per-dataset freshness badges from timestamp.json, degrade gracefully (fall back to Sleeper's off_snp from /v1/stats/nfl/regular/{season}/{week}, or to the last good data), and design usage metrics so target, air-yard and xFP shares (from pbp) still work without snaps.
- [high] No free in-season man/zone, alignment or routes data leads to overclaimed matchup analysis. — mitigation: Label matchup components explicitly (historical tendency vs current-season measured vs estimate), shrink priors, backtest, and limit matchup weight in start/sit until it shows accuracy gains.
- [medium] Licensing and ToS exposure in a monetized Google Play app: FTN CC-BY-SA share-alike, NFL/NGS/PFR data owned by third parties, FantasyPros ECR scraped by DynastyProcess, Open-Meteo free tier non-commercial. — mitigation: Show only derived aggregates in-app with attribution (nflverse, 'FTN Data via nflverse'). Don't republish raw datasets. Buy an Open-Meteo commercial plan or use NWS/met.no. Get consensus rankings from licensed or permitted sources. Get a legal read before monetization.
- [medium] CORS and rate limits: release assets have no ACAO header, and raw.githubusercontent.com unauthenticated limits have been tighter since May 2025. — mitigation: Do all ingestion in GitHub Actions and serve the app only same-origin JSON from GitHub Pages. Version the files and cache them in the service worker.
- [medium] The injury feed is newly re-sourced (nflapi, Aug 2026). Its schema differs from the dictionary (no date_modified) and it gives only one row per player-week. — mitigation: Snapshot injuries daily in the ETL to build the practice progression, validate the schema on every run, and alert or fail soft if columns change. Consider Sleeper player injury_status as a cross-check.
- [medium] GitHub Actions scheduled runs are delayed at busy times or auto-disabled after 60 days without repo activity, so data silently goes stale. — mitigation: Use odd-minute crons, add a keep-alive commit workflow, and publish a status.json that the app checks and surfaces. Add a workflow_dispatch manual trigger.
- [medium] Coverage priors from 2025 participation go stale when a team's defensive coordinator or secondary changes. — mitigation: Keep a DC-change table, shrink priors toward league average in proportion to staff and personnel turnover, and blend in in-season FTN blitz/box and PFR coverage signals as weeks accumulate.
- [low] Mobile payload bloat if raw files (pbp ~20MB parquet, depth charts 62MB CSV, participation 49MB CSV) reach the client. — mitigation: Precompute aggregates server-side, keep the latest depth-chart snapshot only, and split JSON by week and position.
