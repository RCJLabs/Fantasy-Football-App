# League platform import

## SUMMARY
## League import: what matters for the plan

**1. Sleeper is the right place to start. It is the only major platform with a free, documented, keyless read API.** Official docs are at docs.sleeper.com, and the base URL is `https://api.sleeper.app/v1`. The API is read-only and has no token, so no OAuth or backend is needed. The only published limit is "stay under 1000 API calls per minute to avoid IP blocking." The `/players/nfl` dump is about 5 MB. Sleeper says to call it at most once per day and save it on your own server.

For a static GitHub Pages app, the cleanest setup is a scheduled **GitHub Action** that does the following once a day:
- fetches `/players/nfl`
- cuts it down to the fields the app uses (id, name, position, team, status, injury fields, depth chart, cross-platform IDs)
- commits a compressed JSON file that the PWA loads

This keeps you within Sleeper's guidance and makes the download much smaller on phones. League, roster, matchup, transaction, trending and state calls can go straight from the browser.

**CORS is not confirmed.** I could not find a source showing that Sleeper sends `Access-Control-Allow-Origin`. My training knowledge says it does, but test it on day 1 and keep a Cloudflare Worker proxy ready as a fallback.

**2. Sleeper's projections and stats endpoints are useful but fragile.** The endpoints are `api.sleeper.app/projections/nfl/{season}/{week}` and `api.sleeper.com/projections/nfl/{season}/{week}?season_type=regular&position[]=...`, with matching `/stats/nfl/...` paths.
- They are undocumented.
- A community GitHub issue from about late September 2026 reports that the v1 projections path began returning empty entries while the `api.sleeper.com` host still worked.
- An older R package says Sleeper removed the stats endpoint from its supported API.
- Sleeper's GraphQL (`sleeper.com/graphql`) needs a session JWT captured by hand from the browser.

Use these only as one optional projection source behind a fallback. Never make them the core of the app.

**3. ESPN is now more important, because NFL.com Fantasy is gone.** NFL.com stopped hosting season-long leagues starting with the 2026 season. ESPN is now the official NFL fantasy game, and NFL.com leagues are being moved to ESPN via espn.com/importnfl. So **skip NFL.com completely** and plan for more ESPN users.

ESPN details:
- The API is undocumented. Reads go to `lm-api-reads.fantasy.espn.com/apis/v3/games/ffl/seasons/{yr}/segments/0/leagues/{id}?view=...`. The base URL moved off `fantasy.espn.com/apis/v3` around April 2024.
- **Private leagues** need the `espn_s2` and `SWID` cookies. Browsers can't attach those to requests to espn.com, so private leagues **need a server-side proxy**. A Cloudflare Worker that forwards the user's cookies and adds CORS headers is the cheap option.
- Public leagues may work from the browser, but that is not confirmed.
- Community reports show intermittent 403/400 errors on ESPN's unofficial APIs in August–September 2026, so build retries and clear error states.
- `espn_s2` is a full session cookie. Keep it on the device only and never store it on the server.

**4. Yahoo now requires approval, and it changed this year.** Yahoo stopped self-serve sign-up for the Fantasy API. Since **2026-07-22**, apps without approval get HTTP 403 "This application is not authorized" on every endpoint. You have to apply at sports.yahoo.com/developer/access and accept the API Access and Use Agreement. Access is read-only (write access was removed around October 2025). You must show the line "Fantasy data provided by Yahoo Fantasy." Developers report 2–4 weeks for approval. Yahoo's OAuth guide supports only the authorization-code grant, so the token exchange needs a client secret and therefore a backend (the same Worker). **Apply now if you want Yahoo in v2.**

**5. Other platforms**
- **MyFantasyLeague (MFL)** has an official JSON export API: `api.myfantasyleague.com/{year}/export?TYPE=...&L=...&JSON=1`. Private data needs an APIKEY or a login cookie. Leagues live on numbered `wwwNN` servers, and registered clients get higher limits. Dynasty players use it a lot, so it is worth adding in v2 through the proxy.
- **Fleaflicker** has a documented public JSON API (`fleaflicker.com/api/Fetch*`) with no auth for public data. Easy to add, but few users.
- **CBS**'s API is described as deprecated. **Underdog** and **Drafters** have no public API, and the browser extensions that support them use internal endpoints. Avoid all three.

**6. Matching players across platforms is mostly solved already.**
- Sleeper's own `/players/nfl` data includes `espn_id`, `yahoo_id`, `gsis_id`, `sportradar_id`, `rotowire_id` and similar fields.
- DynastyProcess `db_playerids.csv` (the same table nflreadr loads with `load_ff_playerids`) is keyed on `mfl_id`. It adds `sleeper_id`, `espn_id`, `yahoo_id`, `fantasypros_id`, `gsis_id`, `pff_id`, `nfl_id`, `fleaflicker_id`, `sportradar_id`, `pfr_id` and others. It is refreshed **weekly** by GitHub Actions.
- I could not confirm the data license, so check it before you redistribute the file.
- Use the Sleeper ID as your internal player key, and use the FantasyPros and GSIS IDs to join expert rankings and nflverse stats.

**Recommended import order:**
1. Sleeper, browser-direct, plus the daily player-dump Action (MVP).
2. A platform-neutral internal model for leagues, scoring and roster slots. Map Sleeper's `scoring_settings` and `roster_positions` into it on day 1 (MVP).
3. Manual roster entry or paste for anyone not on Sleeper (MVP/v1).
4. ESPN through a Cloudflare Worker for private leagues (v1).
5. Yahoo after approval, and MFL, both through the Worker (v2).
6. Fleaflicker (later).
7. Never: NFL.com, CBS, Underdog/Drafters.

**What needs a backend proxy:** ESPN private leagues, Yahoo OAuth, MFL logins, and any source that blocks CORS. Sleeper reads need none, assuming the CORS check passes.

## FINDINGS
- [high LB] **Sleeper - auth and base URL**: Sleeper's public API is a free, read-only HTTP API with no token. The base URL is https://api.sleeper.app/v1 and the official docs are at docs.sleeper.com. — No OAuth or API key is needed because the API cannot change anything. Users are found by username (GET /user/{username_or_user_id}). There is no email lookup. Wrappers agree that Sleeper's docs cover only part of the endpoints that exist. (https://docs.sleeper.com/)
- [high LB] **Sleeper - rate limit**: The only published guidance is to stay under 1000 API calls per minute or risk an IP block. ## RISKS
- [high] Sleeper might not send CORS headers (unverified), or might add restrictions later. That would break the no-backend MVP. — mitigation: Test on day 1 from the real origin. Keep every Sleeper call behind a single fetch wrapper so a Cloudflare Worker proxy can be switched on with one config change.
- [medium] Undocumented Sleeper projections and stats endpoints change or go empty mid-season (one community report says this already happened around late September 2026). — mitigation: Try both the .com and .app hosts, check that responses actually contain stats, and treat Sleeper as one of several projection sources so the consensus degrades gracefully.
- [medium] ESPN's undocumented API changes host or format, or returns 403/400 errors (base URL moved in 2024; 403/400 reports in August–September 2026). — mitigation: Keep the ESPN adapter isolated, track the cwendt94/espn-api repo for fixes, use backoff and a plain User-Agent, and show clear 'ESPN unavailable' states.
- [high] Handling ESPN espn_s2/SWID cookies or MFL login cookies exposes full user sessions. A leak or logging bug could compromise user accounts. — mitigation: Store credentials only on the device (encrypted IndexedDB where possible). The Worker passes them through without storing or logging them. Explain to users what is being shared and let them revoke it by logging out of ESPN.
- [medium] Yahoo access may be denied or delayed for a solo-dev app, or have its terms changed. The license can be ended at Yahoo's discretion. — mitigation: Apply early, design the product so Yahoo is optional, and offer manual roster entry as a fallback for Yahoo users.
- [medium] Redistributing data with unclear licenses (DynastyProcess ID map with no LICENSE file found; Sleeper projections possibly licensed third-party data; Sleeper API terms for commercial apps not found). — mitigation: Check the license files before bundling. Prefer nflverse CC-BY data for derived files. Contact Sleeper and DynastyProcess before monetizing. Show attribution.
- [low] GitHub Actions scheduled jobs run late or get disabled after 60 days without repo activity, leaving players.json stale (wrong injuries or teams). — mitigation: Show the data timestamp in the UI, add a keep-alive commit or a manual-run button, and fall back to a direct client fetch of /players/nfl if the cached file is more than 48 hours old.
- [low] Players dump is large (about 5 MB or more) for mobile or TWA users if fetched directly. — mitigation: Serve a slimmed, compressed version from Pages and diff-update it daily.
