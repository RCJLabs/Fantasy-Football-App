# Review of plan v1 (2026-10-15)

Four independent critics reviewed draft v1 of PLAN.md: evidence consistency, solo-dev feasibility, completeness, and football methodology. Each issue has a severity, the plan text it objects to, and a proposed fix. PLAN.md v2 takes in all high-severity issues and most medium ones. Figures the critics computed themselves appear in v2 labelled `[own calc]`.

######## EVIDENCE (20 issues)
OVERALL: The plan's [verified] claims about nflverse, GitHub, Cloudflare and Claude pricing mostly hold. I re-checked repo visibility (public), the 2026 calendar, lines existing only for Weeks 6–7, the injuries schema and the Claude prices, and all match. The serious failures are licensing positions that contradict the research's corrections: published xFP and FTN shards are treated as exempt from share-alike, a derivative of the GPL DynastyProcess ID map ships in players.json, and nflverse data is called plainly CC-BY with no caveat for PFR and NGS. The archive spec also can't support the backtest it exists for. The evidence labels are applied inconsistently: third-party code and training knowledge appear as [verified] or [reported], single unopened sources as [reported], and design choices as [verified]. Several corrections were also dropped: the Sleeper v1 projections path, the PFR proxy nuance, the win-probability range caveat, FantasyPros' contacts and the need for RotoWire's permission.

[high] §§4 Key decisions: Licensing rule
  QUOTE: FTN- and ffopportunity-derived **datasets** are CC-BY-SA, so we publish aggregates with attribution and don't publish them as a dataset product. `[design]`
  ISSUE: This contradicts the research's licensing reading. methods.md (Missed, high) says 'any redistributed derived dataset, such as cached xFP JSON on GitHub Pages ... needs attribution and share-alike licensing'. sources.md says adapted data 'such as blended projections published as JSON, may have to carry the same licence'. The plan publishes exactly such files: the 'usage/xFP' and 'matchup tables' shards go to public Pages (§4 diagram; Phase 1 outputs). CC-BY-SA has no exception for 'aggregates' or for things that aren't a 'dataset product'. Labelling the rule [design] hides the fact that it is a legal interpretation the research does not support.
  FIX: Replace with: "Any published shard containing FTN-derived values (ftn_charting, 2023–25 participation) or ffopportunity-derived values is licensed CC-BY-SA 4.0. Its manifest entry carries the licence and credits ('FTN Data via nflverse'; ffopportunity). These values live in separate shards so share-alike doesn't spread to other data. Whether pure numeric aggregates are copyrightable at all is `[unverified]`, so we comply rather than rely on it." Add a per-shard licence field to the contracts/ schema.

[high] §§5 Phase 1 golden test and exit criteria; §6

  ISSUE: This mixes up engine bugs with differences in stat source. Many mismatches won't be scoring bugs. nflverse stats_player has no team defense line, no TD-length fields (pass_td_40p, rush_td_40p), no Sleeper-style reception-length tiers (rec_0_4 … rec_40p) and no pick-six field; these would need pbp aggregation [verified: columns of stats_player_week_2026.csv]. The exit gate 'matches Sleeper points on ≥3 past weeks for every league you play in' could therefore block Phase 1 indefinitely in any league with DEF, K, IDP or distance bonuses. The engine scores Sleeper projection lines, which already use Sleeper's stat keys, so the nflverse mapping isn't needed for the MVP at all.
  FIX: Split the test in two. ######## DOMAIN (16 issues)
OVERALL: The plan's foundation is directionally right: a projection consensus, P(play) and Vegas as the main environment signal. But several specification errors would mis-rank exactly the decisions the app targets. The start/sit objective ignores the option to swap a player after inactives are announced, availability is probably discounted twice, the opponent-defense (DvP) multiplier double-counts matchup information, and K and DST are left out of the MVP. The in-house baseline is half of the MVP consensus, yet it is underspecified (vacated targets, QB changes, game script, TD allocation) and gets equal weight with no pre-ship backtest, even though one can be run now on nflverse 2021–2025. On evidence, the plan dismisses population-level injury risk too readily and trusts noisy per-CB stats too much.

[high] §§2 Start/sit optimizer
  QUOTE: Maximize expected points over legal slot assignments (brute force is fine). FLEX/SUPER_FLEX gets the latest-kickoff eligible player, and Questionable late-game players go in FLEX.
  ISSUE: The objective values a Questionable starter at P(play)×μ. That is only correct when no swap is possible. Inactives are posted about 90 minutes before each kickoff and Sleeper locks each player separately (training knowledge, verify). So a Q player with an eligible bench alternative kicking off at the same time or later is worth P·μ_Q + (1−P)·μ_alt, not P·μ_Q. Example: P=0.70, μ_Q=15, μ_alt=10. The plan's objective scores this 10.5 vs 10, a coin flip; with the swap option it is 13.5 vs 10, a clear start. The FLEX rule is a placement heuristic on top of a mis-specified objective. The optimizer will bench Q players it should start, and the 'gain vs current lineup' number will be wrong on the most common contested decision.
  FIX: Make the MVP objective two-stage. For each candidate lineup, enumerate inactive scenarios for the Q and D players (2^k, k usually ≤4). In each scenario, re-optimize only the slots whose eligible replacements kick off after that player's inactive-reveal time (kickoff − 90 min, from games.csv gametime). FLEX/SF placement then comes out of the optimization instead of a rule. Add an 'I won't check inactives' toggle that falls back to P·μ. Once inactives post, collapse P to 0 or 1.

[high] §§1 item 2 / §5 Phase 1 projections
  QUOTE: Projections v0 = mean of Sleeper (RotoWire) and the in-house baseline, rescored. Distribution = P(play) mixture × σ(position, μ).
  ISSUE: The plan never says whether each source's number is conditional on playing or already discounted for availability. Averaging an already-discounted source with a conditional one and then multiplying by P(play) discounts every Questionable player twice. Example: RotoWire at 0.7× full, in-house at full, P=0.7 gives 0.85×0.7 = 0.60× full instead of 0.70×, about 15% low on exactly the contested players. Props are conditional by construction: books generally void player props if the player doesn't play (verify per book). Props are also medians, not means. The rule 'a source that drops a player counts as weak evidence he won't play' has the same ambiguity: is that a 0 in the mean, or evidence for P(play)?
  FIX: Add an availability-convention field per source to the Projection contract. Convert every source to conditional-on-active before averaging, or exclude Q/D players from any source whose convention is unknown. Treat a missing or zero projection only as P(play) evidence, never as a 0 in the mean. Apply P(play) exactly once. Add a Phase 0 spike: compare RotoWire projections for Q/D players with the same players' prior-week projections to infer its convention. Convert prop medians to means with a fitted position skew factor.

[high] §§2 Matchup layer
  QUOTE: (2) Opponent-adjusted xFP allowed by position, shrunk toward last season, capped at ±10–15%.
  ISSUE: (a) Double counting. The consensus already contains RotoWire, which is matchup-aware, and a baseline driven by Vegas. (d) Weather (item 6) is the same trap. My check of nfldata games.csv 2015–2025 finds the game-total residual vs total_line is +0.7 ± 2.0 at ≥20 mph wind (n=47).   FIX: Estimate DvP as the residual of position-level xFP allowed after conditioning on the opponent's implied total.
